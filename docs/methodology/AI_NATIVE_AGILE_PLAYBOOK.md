# AI 原生敏捷探索笔记：个人实验与方法总结

> **核心目的：** 基于“一个人 + AI”高密度实验，验证在 Agentic Engineering（智能体工程）时代，敏捷流程该怎样变化。
> 
> **实验结论：** AI 把执行成本降到极低，但验证成本没有下降，反而成为主要瓶颈。AI 时代敏捷实践的重心，正在从“管理执行”向“设计验证与授权”转移。
> 
> **NOTE：** 本文纯属个人实验中的观察、踩坑与思考总结，带有较强的个人体感，并无行业普适性，持续迭代中。

***

## 一、 敏捷依然需要

### 1. 敏捷三支柱恰好是 AI 协作的底层逻辑

**透明 Transparency（状态外化）：** 敏捷用信息透明，统一语言，一致理解，来消除信息差，抹平沟通障碍。对应着用状态外化去解决 AI 天然存在上下文漂移、窗口失忆、状态不同步问题。

**检视 Inspection（独立验证）：** AI 存在幻觉、同源偏差和自我美化等缺陷，需要用独立机制来做检视、回顾。

**适应 Adaptation（动态迭代）：** 发现问题，持续反馈，持续调整。对应 AI 产出不确定，流程需要具备熔断、回退、经验沉淀的自适应能力。

### 2. 敏捷不是被 AI 淘汰，是被 AI 升级

**敏捷的骨架保留：**

| 敏捷特性 | AI时代的映射 | 为什么更重要了 |
| :----- | :----------------- | :-------------------------------------------------------------- |
| 应对不确定性 | 渐进明细，小单位内计划细化 | AI产出不确定 + 需求不确定 |
| 小步快跑 | 颗粒度拆分（INVEST原则） | 颗粒度越小→人越容易描述→隐形假设越少→AI越容易对齐→验证越清晰→反馈越迅速 |
| 持续反馈 | 踩坑→沉淀→反哺 | AI像是刚诞生的超级神童，能力极强，但一张白纸且极度不可控，需要培养。他不记得上次踩过的坑，必须将经验沉淀反喂回去，持续反哺。 |
| 进度透明 | 状态外化到文件 | AI换窗口就失忆，文件是唯一可靠的状态载体 |
| WIP限制 | 以验证速度为瓶颈，不以生成速度为瓶颈 | AI生成快→在制品无限堆积→人验证跟不上→验证税指数增长 |
| 可持续节奏 | 设计人机协作的可持续节奏 | AI可以无限跑，但人的注意力是稀缺资源 |
| 自组织团队 | 人机自组织，自运转节奏 | AI跨角色壁垒被打破，团队更扁平化 |

**敏捷的关节发生位移：**

- **交付逻辑：** 从 “交付承诺” 变成 “对齐节奏”。
- **工作重心：** 从 “人写代码” 变成 “人设计验证机制”。
- **角色定位：** 角色重心整体上移，从执行者变成定义者与验收者。

### 3、核心观点

- AI没有让敏捷过时，它让敏捷的每一个原则都变得更可执行。
- 不是敏捷需要AI，而是AI需要敏捷的颗粒度与验证机制，敏捷的每一个核心特性在AI时代都有了新的着力点。
- 团队最大的风险会变成：以惊人的速度，把错误的事情做得很漂亮。AI把执行成本降到极低，人真正稀缺的是判断和授权设计。

## 二、 踩出来的协作体系

这套体系并非自上而下设计，而是在“一个人 + AI”的极限生存实验中，针对真实痛点的产生。

### 1. 主要流程：

**协作模式：**
主控 Agent承担技术顾问、需求讨论、流程推进、文档维护；执行 Agent承担代码生成、测试编写、code review等执行任务。

**工作流：**

- **需求讨论（Project Setup）：** Init → Arch → Design → Env → Rules。输入想法，主Agent引导探讨，确认需求方案，版本Roadmap。规则、约束、权限、流程剧本搭建。
- **迭代层级：** 渐进明细，动态维护Backlog，Epic → User Story → Acceptance Criteria → task 逐级拆解，择优确认当前Sprint Goal，Sprint 结束做retrospective复盘，沉淀复用经验。
- **Story 容器化（任务层loop循环）：** 需求确认 Intent（任务意图）/ Spec（功能规格）/ Plan（实施计划）→ 实现Build → 验证Test → 反馈、迭代 → 回顾、记录 → 触发下一个Story。
- **人机协作：** 人跑脚本 → 生成开场白 → AI读规则 + 加载Skill → 复述（人拍板）→ 执行 → 贴diff（人验收） → 收尾脚本 → Review（人判断）。人的动作只有三类：启动、决策、验收。

### 2. 协作架构

经验层（复盘、实验）→ 流程层（脚本）→ 方法层（Skill）→ 规则层（约束+决策授权+工作流）→ 文档层（事实源）→ 代码层。

核心逻辑：文档即代码，规则即指令，经验可复用

### 3. 核心机制

**决策分级授权：** 针对 “所有决策都问人 → 人疲劳跟不上 → 关键决策被淹没” 的痛点

- L1：有先例、可回滚，AI自动执行
- L2：中等风险，AI 拍+人抽查
- L3：价值判断、方向原则，人拍
- L4：不可逆、影响面大，人+会签（单人隔日冷静期审批或冷启动二次确认）。

**三层工作流：** 针对“讨论中反复改指令、执行中不断变需求导致遗漏，混乱” 的痛点

- 讨论层：只聊方案、不派任务，允许多角度发散
- 敲定层：最终确认后，一次发全指令
- 执行层：严格按指令执行，禁止跳层

**独立验证与同源偏差：** 针对 “实现 Agent 自己写测试，覆盖不全面、标准从实现反推” 的问题

- 测试分层 T1-T6：T2/T3 由独立测试 Agent 从需求推，切断同源偏差；实验证明物理顺序切不断，只有独立性才能切断。
- 独立验证：冷启动 Review，只看产出做判断。异质模型初筛收敛，人拍板。

**状态外化与事实校验：** 针对 “换窗口失忆、状态不同步” 的痛点

- Markdown 管上下文，JSON 管字段，AGENTS.md 管行为。
- 新窗口先读 git log + 状态文件 + 代码，复述理解后再执行。不依赖对话记忆。
- 所有状态变更实时写入，不存于对话上下文。

**熔断与回退：** 针对 “AI 陷入死循环、越改越乱” 的问题

- 熔断规则：迭代超 3 轮 / 改动量上升 / 超时 30 分钟强制交人。
- 回退机制：建立git 提交纪律，scope 白名单锁范围。改坏可回退。

**颗粒度拆分：** 针对 “需求描述不清、AI 理解跑偏” 的核心痛点

- 大任务拆小，直到人能描述清楚、AI 能对齐为止。颗粒度越小，隐性假设越少，沟通带宽消耗越低，对齐越快。

**规格冻结：** 针对 “AI应对模糊意图时，总是达不到人心中所期待效果”的痛点

- AI是没有手感的，你在用眼睛画，它在用尺子报数，不让 AI 重新理解，让它按冻结规格渲染，防止风格漂移。

**半自动陷阱：** 针对 ”人对于AI给出的计划、实现等无法看懂，审核时容易糊弄、倦怠，甚至对AI产生依赖，最终流于形式“ 的问题

- 不是AI每一次发回的计划人都能看得懂，跟得上。要让 AI 先把产出翻译成“选项 + 依据 + 风险”，人只看摘要、证据、风险标记。

### 4. 总而言之

**流程解决痛点：** 每一个核心组件的出现都对应真实痛点，都是踩坑之后的解决方案。

**人的动作高度收敛：** 人的动作只有三类 —— 启动任务、关键节点决策、最终验收，其余环节 AI 端到端跑通。

**敏捷的内核依然成立：** 迭代思维贯穿始终，每一步遇到障碍→重新评估→调整方案，本身就是一次完整的敏捷迭代。

## 三、 实验中洞察真相

### 1、过程中提炼的发现

**AI 强在造新，弱在改旧：**

- 从 0 到 1 能力极强；修改存量代码时，看不到历史妥协与隐性依赖，极易“改一个 Bug 引出三个新 Bug”。
- 对策：新建功能给 AI 更大自主权；存量代码修改设置高决策级别、强制范围锁定、回归测试护航、熔断规则兜底；拆到极小颗粒度。

**AI 天然缺乏“最小改动”的自觉：**

- 让改一个函数，它会顺手重构整个文件。
- 必须用 Scope 白名单锁死改动范围。

**AI 是目标导向而非规则导向：**

- AI按指令执行，不按规则自省，被禁令挡住会换路继续试。
- 规则管不住它，权限闸门（CI/Hook/Scope）才管得住。
- 让AI自动读Skill这种幻想要靠脚本实现。

**AI 是个人的放大器：**

- 它放大的不是审美，而是判断密度。你有判断标准，它产出高质量；你没标准，它快速产出垃圾。
- 输入质量决定输出质量，模糊需求在 AI 手里会放大成灾难。
- 颗粒度越小、规格越清晰，返工成本越低。

**验证税是 AI 时代的核心矛盾：**

- AI 提效的真正瓶颈不是生成速度，是验证速度。
- 对策：验证左移（AC可执行、可grep、边界明确）；机器审查机器，独立、异质；人只看关键路径（高风险变更+业务逻辑+边界条件）；Gate条件客观化（不信任模型自述，信任真实产物）；WIP限制。

**AI时代的核心是流程设计：**

- AI时代的核心竞争力，不是审的过来，是设计出正确的授权边界。
- AI将产出翻译成人能判断的状态，降低认知负担，保留最舒适自然的判断权。

**颗粒度就是对齐精度的调节器：**

- AI强在执行精确规格、弱在从模糊输入猜规格。
- AI 提效的前提，是人要把“定义”和“验收”做得更清晰。
- 颗粒度的拆分也是一套让人将话讲清楚的机制。

**缺乏机制保障时，半自动可能比全自动更危险：**

- 不是每次AI发回的计划人都能看懂，审核了几次就开始出现糊弄现象，被迫放弃检查。人会越来越依赖AI，经常丧失最基本的判断力。想让AI全智能，但它做不到，人就反而会为了它的错误买单。
- 解法：降低预期，设定合理审核机制。决策分级，让AI将产出翻译成人能做判断的形态，降低验证税。

**AI报告的完成不等于完成：**

- AI幻觉，长对话工具人化漂移，反思被预埋引导。
- 幻觉靠事实校验，漂移靠状态外化，引导靠独立复盘。不信自述、不靠记忆、不被引导，用机制保证可靠性。

### 2、让发现可被验证 —— 对照实验

本体系的核心机制，均通过“单人+AI”环境下的对照实验跑通验证。完整数据见 `docs/experiments/` 目录。

- **AI 协作流程对照（手动 vs 自动）：** 发现 AI 不会自动加载 Skill，需靠脚本触发。
- **状态管理对照（JSON vs Markdown）：** 验证 JSON 管字段约束、Markdown 管上下文、AGENTS.md 管行为的互补关系。
- **测试设计对照（单 Agent vs 双 Agent）：** 发现物理顺序切不断同源偏差，真正能切断偏差的是独立性（独测不看实现，只推需求）。
- **文档驱动流程验证：** 验证“文档即代码”，文档不仅是给 AI 的指令集，也是解决上下文漂移的状态容器。
- **决策分级与熔断验证：** 实测 L1-L4 让人的决策负担降到 40%；熔断规则有效防止了 AI 死循环。
- **多 Agent 协作验证（主控+执行）：** 验证多 Agent 互判可行，但需配合异质模型与人的事实校验锚点。
- **AI 提问机制验证（带置信度追问）：** 验证“一次问一个 + 置信度 > 95%”能有效降低人机信息差，减少误解。
- **回退与范围锁定验证：** 验证了 Git 回退兜底与 Scope 白名单为修改存量代码提供了安全边界，有效降低了 AI 破坏隐性依赖、越权修改的失控风险。
- **颗粒度与规格冻结验证：** 验证了通过冻结结构化规格（如坐标、色值）来约束生成，能显著减少 AI 每次“重新理解”带来的风格漂移。
- **独立审查机制验证：** 验证出，用“冷启动新窗口”独立 Review 机制，能有效发现执行 Agent 自审时遗漏的盲区，打破“自己审自己一切良好”的错觉。

## **四、 人机协作框架推演**

个人项目验证了方法论的可行性。工作中的流程需要升级，核心是将调度逻辑交由确定性系统接管。

### **工程架构推演：**

#### **1、剧本 + 引擎**

**引擎调度：**

个人项目中主导Agent扮演读状态、状态流转、调度执行Agent。本质上是用大模型模拟调度器。

但工作中该角色需替换为确定性Orchestrator调度引擎。因为大模型做调度有致命缺陷：不确定（遗忘、幻觉）、不可解释（逻辑黑盒）、无法强制拦截（AI目标导向会绕规则）。

**分层架构：**

*   底层基座（Harness）：模型调用、工具执行、沙箱、日志可观测性。
*   调度中枢（Orchestrator）：状态流转、卡点暂停、调用Agent、规则强制执行
*   业务规则层（Playbook）：定义决策分级、验证机制、流转规则、异常处理。

平台给能力，人定规矩。引擎负责“能不能跑”，人负责“跑得对不对，安不安全”

**剧本设计：**

实验过程中总结的“敏捷+AI全生命周期”以及“文档即代码-文档责任说明”。这些结构、规则、流转设计本质就是一套剧本，配置给调度引擎。没有剧本，引擎就是空转，没有配置的规则，AI就会天马行空。

#### **2、多Agent交付流水线**

需求分析 Agent → 架构设计 Agent → Gatekeeper 排雷 → 开发 Agent → 独立测试 Agent → 独立审查 Agent → 流程调度PM Agent → 部署发布DevOps → 经验、复盘、沉淀

设计原则：

*   流水线不必完整相同，可按任务复杂度分级路由。人只在关键闸门介入。
*   逻辑自洽必然导致验证失败，需切断同源偏差独立验证。
*   状态机驱动而非对话驱动：用结构化文件定义职责、输入输出和状态转换，避免混乱。

#### **3、文档即代码，责任流转，流程矩阵：**

详细可参考《AI敏捷全生命周期》，《AI敏捷文档责任》。

#### **4、平台之上即舞台**

平台提供通用能力，业务需要业务规则。

为何不能直接使用平台？就像芯片有基础功能，但上层业务需自己设计；就像操作系统标准内核，使用时候仍要裁剪定制；就像TCP是标准协议，但公司可能是用UDP业务封装模拟自定义成TCP。平台是“最大公约数”，业务是“最小特优解”。

AI的PaaS给你的是概率模型 + 工具链 —— 模型会飘、会幻觉、会绕约束。所以必须在平台之上定义业务规则层：什么任务自动、什么必须人审、什么算完成、什么情况要停。

### **角色与组织推演**

#### **1、角色变化**

**人从执行者到设计者：** AI时代不是角色消失，而是角色重心上移，从执行上移到定义与验收。

**AI 能判对错，不能判该不该：** AI处理不了的冲突、模糊、风险，需由人来扛。

*   人的审查面 = 范围 + 口径，不是任务清单。
*   任务清单回答“有没有做”，范围回答“该不该做、做多了没”，口径回答“做得对不对”。人审后两个，不审第一个。
*   人的注意力要花在只有人能判断的地方，别做打卡机。

**三道闸门：** 人在最主要的三道闸门出现。

*   Plan Gate —— 确认AI计划
*   Acceptance Gate —— 验收成品
*   Retro Gate —— 复盘、沉淀、上下文、协作

**决策带宽 —— 人是新瓶颈：** 以前是人手执行够不够，现在是人的决策带宽够不够。需像操作系统一样资源合理分配，轮转调度。

*   WIP限制：一人同时最多盯3-5个任务
*   异步检查：Agent产出后进入审查队列，人按优先级处理，不阻塞Agent继续下一个Story。
*   决策分级：L1 / L2 放给AI，人处理 L3 / L4 。

#### **2、组织形态变化**

人类组织按职能岗位切分，是因为人学习专业需要时间。AI打破了跨专业、跨沟通的壁垒，真正难在对于当前对象完整上下文的理解。所以会向“围绕一个对象持续理解”的方向进化。

*   小快业务前锋：前台小团队 + AI前线打头阵，快速跑通，敏捷响应 。
*   稳强规则中坚：强规则中台，将规则组件库，可复用的判断、能力、知识沉淀成公共底座，所有团队随时调用，避免从零开始。
*   深难决策专家：定海神针，最后的闸门。处理新问题、高风险、不可逆决策，承担责任。

真正的扁平化不是减少层级，而是缩短决定距离 —— 让拥有上下文、有权行动的人，在最接近问题的位置做决定。最懂游戏规则的前线直接授权L1-L3拍板。当事情不可逆，动摇根基才向上报告L4会审。

#### **3、竞争力锚点的转移**

当技术实现的壁垒被AI迅速抹平，竞争力锚点开始转移向规则和治理

*   上下文壁垒：把内部业务知识沉淀成 AI 能读懂的结构化资产，能让AI懂业务，而不只会写代码
*   信任机制壁垒：当AI生成海量代码方案时，能设计出合理的决策边界和独立验证机制，管住AI，安全释放 AI 产能。
*   组织学习速度：快速将前台经验沉淀进中台，并瞬间赋能给所有Agent，全网免疫，把个体经验快速复制成组织能力。

以后组织的竞争力，将转向 “我的人机协同规则设计的多好“、”我的组织经验复制的多快”

### **AI治理与协同自动化**

#### **1、需求讨论该怎么自动化**

不是让平台替你做决定，而是将“人机对话”的过程自动化，将“人必须做决定”的节点显性化。

**LOOP循环：** 人触发 → 平台调度唤醒需求AI，反复追问 → AI生成草稿 → 平台暂停等审批 → 人批准 → 平台继续调度 → 再暂停 → 人审…… 如此循环。人只负责在关键节点做决策和审批，流转、调度、触发自动推进。

**AI追问模式可做文章：** 

*   AI追问必须一次一个问题，避免信息过载。
*   附带猜测和置信度，判断置信度，低于阈值则循环。
*   追问时给出多条建议方案，推荐原因，翻译成让人最方便做选择的模式。
*   必须设置回退机制，可追溯。

总之到人评审时，AI已经将所有模糊点澄清。

#### **2、“刚出生的神童”如何教养**

AI能力极强但极度不可控。风格飘忽不定，即使上下文颗粒度都做好，甚至同一Agent可能每次生成的结果都不一样。这是AI作为概率模型天然的缺陷。需多层管控将“风格一致”锁死。

*   硬约束：锁住底线，规范CI强制跑，不过不允许合并。
*   强中台：强制优先调用公共组件库，缩减自由发挥度。
*   范例驱动：Skill中放黄金范例，输出对齐，锚定风格。
*   参数控制：代码生成调高稳定性。需求头脑风暴调高灵感度。
*   风格审查：可设置专门产出风格审查Agent，不一致打回。

让AI变成符合企业习惯的员工。不能靠运气，必须靠流程设计去”教养”它，靠机制去消除它的随机性。

## 五、 流程的终局 —— 搭桥到拆桥

### 1. 现在流程的本质：让人跟上AI

我们设计的层层文档、审批节点、校验机制，本质上是在给 AI 装“减速带”和“翻译器”，是为了解决人跟不上AI速度的三大瓶颈：带宽、信任、责任。目的是让 AI 的产出降到人类能跟得上、看得懂、能做出判断的速度。

### 2. 未来的演进方向：让AI替人消化过程

当 AI 被喂得足够成熟，懂业务（上下文极全）、自验证强（Eval全绿）、高可信（判断零差错），“减速带”会逐步拆除，流程会发生坍缩，workflow变得极薄。

终极极度理想化形态：到那一天，可能大部分流程都被AI在内部自动消化了。AI从海量业务上下文发现机会，直接生成方案供人选择。AI内部完成推理，不需要显示输出给人看。AI自测自修，黑盒形态，人只启动给目标和看结果。当然到这一步还有很多的路要走，很多的问题需要解决。

### 3. 搭桥与拆桥

现阶段搭桥：既不能不让AI跑（浪费），又不能让AI乱跑（灾难）。所以要设计减速带让AI在人类的信任边界内跑

未来拆桥：当AI的可靠性被验证，我们需要做信任升级的推动者，主动拆掉不必要的节点，动态调整审批级别，而不是死守流程。

流程设计的终极价值，不是设计死流程，而是设计一套随着信任度提升、流程越来越薄的演进机制。

## 六、 最后的最后

**AI时代敏捷的内核没有变：** 变的是承载方向和协作对象。迭代思维亦贯穿始终，每一步都在遇到障碍 → 重新评估 → 调整方案。这本身就是一次次完整的敏捷迭代。

**人的价值从未被消减：** 我们从 “管理人的协作” 走向 “设计人机的协作”，从 “提升执行效率” 走向 “管控验证风险”。从执行层，上移到了规则与决策层，而这里，正是人作为智慧主体真正的护城河。

**在‘信任度’与‘流程厚度’之间寻找最优解，正是 AI 时代效能设计的破局之匙。**
