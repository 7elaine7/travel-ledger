## Sprint 0

### 目标

账户体系从零搭建，E-01（全部）

### Story 列表与 AC

#### S0-01 创建第一个账户

> 原始规格原文：

作为首次打开 App 的用户，
我想在空白输入框中给自己起名字、点击"创建"，
以便拥有一个独立账本，开始记账。

（本 Story 的验收标准由 AI 在执行前自行拆解，人审查后确认）

**AC（2026-09-11 计划确认后定稿）：**

1. 首次打开（profiles 表为空）时，页面呈现账户创建引导：一个空白名字输入框 + "创建"按钮，无任何预设账户。
2. 名字去除首尾空格后不能为空；纯空格点击"创建"时拦截并提示，不写库。
3. 名字长度上限建议 20 字符，超出禁止创建并提示（数值待确认）。
4. 点击"创建"写入 profiles 表：id（自动生成）、name（trim 后）、createdAt（当前时间）。
5. 创建成功后自动以该账户身份进入记账首页。
6. 建议允许重名（以 id 区分），不做重名拦截——待确认。
7. 刷新/重开页面后账户仍存在（IndexedDB 持久化）；已有 profiles 时不再出现首次创建引导。

#### S0-02 切换和查看已有账户

> 原始规格原文（含已给定的部分 AC）：

作为已有多个账户的用户，
我想在顶部下拉菜单中看到所有账户列表，并点击切换，
以便查看不同人的账本，且下次打开时记住上次选的是谁。

验收标准（部分，其余由 AI 补充）：

- 顶部右上角显示当前账户名，旁边有下拉箭头（▼）
- 点击下拉，展开所有 profiles 表中的账户列表

**AC 正式版（2026-09-11 人拍板，取代上方 AI 草案）：**

1. **AC1**（原文）：首页顶部右上角显示当前账户名，旁有 ▼
2. **AC2**（原文）：点 ▼ 展开所有 profiles 账户列表（按创建时间正序，先建的在上）
3. **AC3**：当前账户在菜单中带 ✓ 高亮；再点 ▼ 或点菜单外区域收起；完成切换后菜单自动收起
4. **AC4**：点选其他账户即切换，严格按 5.2-C 顺序执行（先清旧 → 再渲染新），不闪现旧账户内容
5. **AC5**：切换完成瞬间，localStorage `lastProfileId` 更新为新选账户 id
6. **AC6**：刷新/重开页面 → 直接恢复上次选中的账户（而非固定第一个）
7. **AC7**（边界·账户被删）：lastProfileId 指向的账户已不存在 → 静默回退到最早创建的账户、修正存储，不报错不白屏
8. **AC8**（边界·库被清空）：profiles 为空 → 回 S0-01 创建引导，同时清除 lastProfileId 残留
9. **AC9**（边界·单账户）：仅一个账户时下拉照常可用，列表只有自己带 ✓
10. **AC10**（方案 a，人拍板）：菜单底部「＋ 新建账户」入口 → 进引导页 → 创建成功后自动进入新账户并成为当前账户。理由：没有该入口，正常使用下用户永远无法创建第二个账户，"可分发、每人独立账本"的定位不成立。
11. **范围边界**：无账户重命名/删除入口，菜单不含任何删除操作；切换有防重入保护（连点菜单项只执行一次切换）

**恢复决策（纯逻辑，已进单测）**：savedId 命中 → 该账户；为空/失效 → 最早创建的账户（菜单第一项）；空列表 → null 回引导。实现在 `Profiles.pickCurrentProfile` / `Profiles.sortProfilesForMenu`。

### Sprint 1 详细拆解

#### Story S1-01：文本录入与智能解析（含完整文本保留）

> 原始规格原文：

作为用户，我想在输入框打字"我今天吃肉夹馍花了50"，点击"记一笔"，
以便系统把整句存下来，同时提取金额 50.00 用于算账，并自动打上"餐饮"标签。

验收标准（AC）：

- 输入"我今天吃肉夹馍花了50" → rawText 保留整句原文，amount = 50.00，category = food
- 输入"去XX景区门票花费100" → rawText 保留原文，amount = 100，category = attraction
- 输入"高速费120" → category = toll；输入"加油300" → category = fuel
- 如果文本中有多个数字，MVP 阶段只提取第一个数字作为金额，完整文本保留
- 如果文本中没有数字 → 不提取金额，触发确认框拦截

> **2026-09-11 人拍板变更：AC4 金额提取口径**（原 AC 文字按规矩保留，本条取代其执行口径）
>
> 多个数字时，按标点切句（**，。；！？、,.;!? 与换行**），每句取最后一个数字，求和作为金额；无任何数字时不提取金额；整句无标点时按整句取最后一个数字。
>
> - 示例："早上花了10，中午花了20" → 10 + 20 = 30；"8月30日加油200，买菜50" → 200 + 50 = 250；"苹果10、香蕉20" → 10 + 20 = 30；"早上花了10中午花了20"（无标点）→ 整句最后一个数字 20；"买了2杯咖啡花了40"（无标点）→ 40
> - 变更理由：连记/补记一句话常含多笔花费，"只取第一个"既会漏算，也会把句首的日期数字（如"8月30日加油200"里的 8、30）误当金额；切句取尾求和贴合"每小句最后出现的钱数"的口语习惯。
> - 已知局限（登记于 B-15，不在本 Story 处理）：① 量词误算（"买了2个包子，花了10块" → 2 + 10 = 12）；② 无标点长句只能取整句最后一个数字（"早上花了10中午花了20" → 20；**空格不是切句符**，带空格同例仍取 20）；③ 整句求和记为单条记录，不拆成多条（见 B-17）。
> - 补充（2026-09-11 小数修复）：英文句点 `.` 仅在"不是小数点"时切句——两侧都是数字（如"3.5"）保留不切；句末点（"共50."）与非数字间点照常切。

#### Story S1-02：写入前强制确认弹框（防误触核心）

> 原始规格原文：

作为用户，我想在每次保存之前，看到一个弹框显示"系统识别结果"，点"确认"才存，点"取消"就放弃，
以便防止语音误识别或打错字导致脏数据入库。

验收标准（AC）：

- 无论语音还是打字，点击"保存"后，绝不直接写入 IndexedDB
- 首先弹出半屏确认弹窗，展示三行信息：📝 原文、💰 金额、🏷️ 类别
- 弹窗底部有两个大按钮：【取消】（红色）和【确认保存】（绿色）
- 点击【取消】→ 弹窗关闭，数据丢弃，输入框保留原文方便修改
- 点击【确认保存】→ 写入 IndexedDB，弹窗关闭，首页列表刷新，顶部汇总刷新，出现"✅ 保存成功"提示

> **人拍板约束（2026-09-11，见本文「Sprint 1 范围调整」）**：本弹窗为文本/语音共用组件，触发接口必须为「接收 rawText / amount / category / happenedAt 即展示」，不得写死为仅由文本输入框触发。日期字段默认今天，可编辑。S1-03 语音已移出本 Sprint（见本文「Sprint 1 范围调整」），本约束为将来接入预留。

**2026-09-11 人拍板：范围扩展**

变更理由：补记场景（如"8月30日加油200"）暴露两个缺口——① 解析出的金额/类别会错，用户没有修正手段；② happenedAt 字段的来源从未定义，补记只能记成今天。

新增 AC（原 AC1–AC5 保留不变）：

- **AC6** 弹窗四项均可编辑：原文（文本框）、金额（数字输入，默认解析值）、类别（6 类可切换，默认解析值）、日期（默认今天，快捷【今天】【昨天】【前天】+ 原生日期选择器）
- **AC7** 金额校验：必须为 > 0 的有效数字；非法时不能保存并提示，不写库
- **AC8** 日期不允许选未来
- **AC9** 入库以弹窗中编辑后的值为准：rawText / amount / category / happenedAt
- **AC10** createdAt 恒为写入时刻，不受日期选择影响

#### Story S1-03：语音录入（自动转文字 + 触发确认弹窗）

> 原始规格原文：

#### Story S1-04：按日期分组的完整流水列表 + 分类小计

> 原始规格原文：

作为用户，我想在首页看到按日期倒序排列的账单，每条显示完整原文，
以便一眼知道这笔钱具体干了啥，而不是只看冷冰冰的"餐饮 50"。

验收标准（AC）：

- 列表按日期分组，最新日期在最上面
- 每条记录展示三行信息：主行完整原文、副行类别+具体时间、右对齐金额（红色支出）
- 每个日期分组底部显示："📊 本日小计：¥XXX"
- 每组内紧挨着"本日小计"上方，自动生成该日的"分类消费明细"
- 仅显示当日金额 > 0 的分类，无消费的分类不显示
- 如果当前账户没有任何账单，显示空状态插画 + "还没有记账，赶紧记一笔吧"

> 口径澄清（2026-09-12 人拍板，原文不动，追加于 S1-04 落地后）：
>
> 「副行'具体时间'的显示口径：显示 createdAt（记录时刻）的完整本地日期时分，并加"记录于"前缀，明确区分于消费日（组头的 happenedAt）。原因：happenedAt 仅含日期无时分，消费时刻不可得。」
>
> 同次验收拍板的交互口径：① 列表排序分组 / 本日小计 / S1-05"今日支出"三个日期口径统一为 **happenedAt**（补记挂消费发生日，不挂写入日）；组内按 createdAt 降序；组头对今天/昨天加尾注。② 弹窗原文输入框 **blur 时自动重解析金额与类别并一律覆盖手动值**（"改了就证明原来的不要了，觉得不好就取消"），日期不参与重解析（B-22 未做，重算会把手选日期重置成今天，属倒退）。

#### Story S1-05：首页顶部实时汇总卡片

> 原始规格原文：

作为用户，我想在列表顶部看到"今日花了多少"和"总共花了多少"，

验收标准（AC）：
