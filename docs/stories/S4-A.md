# S4-A 载录页表单实装 + 解析预填

> 本文件是 S4-A 的方案（intent + spec + plan + 测试重点）。AC 全文在 SPRINTS.md Sprint 4 章节。
> Gitee 工作项：挂在 E-02 下。

---

## Intent（业务意图）

**为什么做**：载录页 S3-06 已完成视觉迁移，但五项（金额/分类/时间/地点/备注）仍是静态展示，无法输入。要让记账主路径闭环，载录页必须变成可交互的表单。

**解决什么问题**：用户从首页输入原文后进入载录页，看到的应该是「已根据原文预填的表单」，可微调后保存。现状是只能看不能改。

**边界**：
- 本次只做「表单实装 + 解析预填」，**不写库**（保存行为不动，留给 S4-B）
- 不做地点解析（PENDING #24）
- 不做日期解析（B-22）
- 不弹 sheet、不动 S1-02 sheet 链与 saveEntry

---

## Spec（需求规格）

**AC 全文见 SPRINTS.md Sprint 4 章节 S4-A**（AC1 ~ AC10）。

**关键行为**：
- 空输入进页：金额空、分类"其他"、日期今天、地点"在途"、备注空
- 有输入进页：用原文解析预填金额/分类/备注
- 预填只做一次，失焦不重解析
- 二次进入重新预填（覆盖残留）
- 时间控件 max = 今天

**数据结构**：五项表单值在内存中维护，不落库。

---

## Plan（实施计划）

**改哪里**：

| 文件 | 改动 |
|---|---|
| `js/record-form.js`（新增） | 纯逻辑模块：`buildPrefill(rawText, todayYmd)` → 五项预填值（复用 Parser.parse / EntryUtils.todayYMD） |
| `index.html` | view-record 内五项换成输入/点选控件（时间用原生 date，max=今天）；分类 6 项改可点选 |
| `css/app-v2.css` | 输入控件手绘风（透明底、字体继承） |
| `js/app.js` | 进载录页时调预填 + 分类点选事件 |
| `tests/unit-record-form.js`（新增） | 单测 8-10 条 |

**步骤**：
1. 建 `js/record-form.js` + 单测（先纯逻辑，无 UI）
2. 改 `index.html` 控件
3. 改 `css/app-v2.css` 样式
4. 改 `js/app.js` 接线（进页预填 + 点选）
5. 人手动验收 AC1~AC10

**依赖**：无（可独立开工）

**风险**：
- Parser.parse 的预填值可能与用户预期不符（低）
- 原生 date 控件样式受浏览器限制（已知，B-23）
