# 实验三：单 Agent vs 双 Agent 测试设计对照实验

> 目的：拆出两个变量的独立影响——顺序（TDD vs 传统）和独立性（同一 Agent vs 独立 Agent）。

---

## 一、实验设计

**需求文档**：实现函数 `sumAmount(text)`，从中文文本提取金额求和。含 4 个示例和 3 条边界。

**三组对照**：

| 组 | 分工 | 顺序 |
|----|------|------|
| A 组 | 单 Agent 自写自测 | 测试先（TDD） |
| B 组 | 代码 Agent + 独立测试 Agent | 测试先，双方上下文隔离 |
| C 组 | 单 Agent 自写自测 | 实现先（传统） |

**对比逻辑**：
- A vs C → 测顺序影响
- A vs B → 测独立性影响

**测量**：测试数量、覆盖边界、测试标准来源、异常输入覆盖、综合场景覆盖。

## 三、结论分析

**判断框架**：
- A ≈ C，A 与 B 有差异 → 顺序不重要，独立性重要
- A 与 C 有差异，A ≈ B → 独立性不重要，顺序重要
- A ≈ C ≈ B → 三组差不多

**实际结果**：
- A 和 C 的测试都出现"实现反推"用例 → 顺序不影响同源偏差
- B 测试全部从需求推 → 独立性切断了同源偏差
- C 组覆盖最广（32 条），多出部分是异常输入和综合场景

**核心结论**：影响测试质量的关键变量不是顺序，是独立性。

## 四、核心发现

### 发现 1：TDD 的物理顺序切不断同源偏差

A 组表面上严格走了 TDD——先写测试，再写实现。但它的测试里仍然出现实现反推用例：

| 用例 | 需求里有吗 | 为什么它测了 |
|------|-----------|-------------|
| 3块5毛→3.5 | 没有 | 它实现时决定"角/毛按十分位累计"，反过来测这个规则 |
| 第2名→跳过 | 没有 | 它实现时把"名"加进了量词表，然后测它 |
| 花了3.5→3.5 | 没有 | 它实现时决定裸小数也计入，然后测它 |

**这说明**：
- 物理顺序：确实是先写测试，再写实现
- 认知顺序：它在写测试之前，已经把实现方案想清楚了

**TDD 在人类开发里有效的核心前提是：人写测试时只考虑需求。但单 Agent 做不到——它在写测试时脑子里已经有了实现方案。**

| 维度 | A 组（TDD） | C 组（传统） |
|------|------------|-------------|
| 物理顺序 | 测试先 | 实现先 |
| 认知顺序 | 实现先行 | 实现先行 |
| 测试是否被实现污染 | 是 | 是 |

**"顺序变量"这个假设被证伪了。**

### 发现 2：同源偏差的本质是"测试标准来源被污染"

不是"测试写得少"，而是"标准答案从哪来"。

- 单 Agent（A、C 组）：测试里混入了从实现反推的用例
- 独立测试 Agent（B 组）：测试标准全部从需求推导，且有"刻意不测清单"

### 发现 3：两种测试互补，不是替代

| 单 Agent 独有 | 独立测试 Agent 独有 |
|--------------|-------------------|
| 异常输入（null/undefined/空） | "不测"清单 |
| 综合场景 | 契约纯净 |
| 历史 bug 复现 | 测试和实现解耦 |

**没有任何一组覆盖全部层次。**

### 发现 4：AI 自测是默认行为

四个 Agent 第一反应全部是找运行时跑测试。B 组代码 Agent 被要求"只写实现不写测试"，自己写了一套内联测试试图跑。

**结论**：文字约束不可靠，环境隔离才可靠。

## 五、测试覆盖五层策略（实验结论落地）

| 层次 | 覆盖什么 | 谁来写 | 原因 |
|------|---------|--------|------|
| L1 契约层 | 需求明写的示例 + 边界 | 独立测试 Agent | 防实现污染 |
| L2 推广层 | 需求规则的直接推广 | 独立测试 Agent | 从需求推 |
| L3 异常层 | null / undefined / 空 / 无数字 | 实现 Agent 补充 | 它知道防御分支 |
| L4 组合层 | 跨需求的综合场景 | 实现 Agent 补充 | 它知道内部函数怎么串 |
| L5 回归层 | 历史 bug 复现用例 | 实现 Agent 补充 | 从缺陷反推 |

---

## 六、实验局限

1. 交叉验证没跑（本地无 node）
2. 需求文档太简单（4 示例 + 3 边界），差异空间被压缩
3. token 消耗未记录
4. 每组只跑一次，单次样本只能作方向性参考
5. 纯正 TDD 的"测试设计者完全不知道实现"无法在单 Agent 模式下模拟

---

## 七、一句话总结

**核心产出**：一张"测试覆盖层次表"——L1/L2 独立测试，L3/L4/L5 实现 Agent 补。

**更根本的结论**：TDD 的物理顺序不能切断同源偏差。同一个 Agent 无论先写测试还是先写实现，认知上都是"实现先行"。真正切断同源偏差的是独立性。
