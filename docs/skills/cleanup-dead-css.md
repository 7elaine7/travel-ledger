# Skill: cleanup-dead-css

## 什么时候用
- PENDING/BACKLOG 里有"死 CSS 清理"类任务
- 迁移页面后发现旧样式无引用
- 例行代码卫生检查

## 前置条件
- 有明确的清理范围（哪几个类名 / 哪个区块）
- 人已确认这次要清理（不擅自扩大范围）

## 步骤

### 1. 定位定义位置
grep 目标类名在 css/ 里的定义位置，报出行号范围。

### 2. 核查引用（关键步骤）
分别在以下位置搜引用：
- index.html
- js/ 下所有文件（注意：有些类名在 JS 里动态拼接，要搜字符串而不是只搜 class）
- tests/ 下所有文件
- mock/ 下的静态稿（如果引用了真实 styles.css，要单独标注）

引用计数为 0 → 可删。
引用计数 > 0 → 保留，并报告"PENDING 描述与实际不符"。

### 3. 执行删除
- 只删 CSS 规则本体
- 相邻空行一起清理，保持格式
- 如果某媒体查询块里只有被删的类，整块删

### 4. 报告
- 删了哪几行（原行号范围）
- 删了多少字节 / 行数
- 花括号配平是否正常
- 是否有"例外保留"的类

### 5. 强制检查点
- 人 Safari 打开应用，确认视觉无变化
- 人触发关键页面（首页 / tab 切换 / 涉及改动的页面）
- 单测：CSS 改动不影响单测，但保险起见跑一遍
- 控制台无红色报错

### 6. commit
格式：PENDING #XX 完成：<一句话>

### 7. 更新 PENDING
- 对应条目移入"已完成归档"
- 描述按实际执行修正（如果发现原描述不准）

## 失败回滚
git checkout css/styles.css

## 已知陷阱
- Safari 缓存：验证时 Cmd+Shift+R 强刷
- JS 动态拼接类名：grep 要搜字符串，不只搜 class
- mock 目录影响：删前 grep mock/，删后报告影响
- 例外保留：有些类看起来死了，实际被某个偏僻页面用（如错误视图）
- 注释陈旧：删规则后，引用该规则的注释要一起改
- 死样式连带：同一区块可能有多条同类死样式，一并核查（但不超范围删）
